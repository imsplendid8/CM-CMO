# 공통 뉴스·논문 브리프

대시보드·텔레그램·이메일은 채널별로 별도 요약을 만들지 않는다. 뉴스 수집 시
`scripts/content_brief.py`가 `data/briefing/latest.json`을 만들고 세 채널이 같은
제목·요약·근거 링크를 사용한다. 내부 데이터에는 중요도·권장 대응도 유지하지만,
텔레그램과 이메일에는 판단 문구를 반복하지 않고 뉴스 요약만 표시한다.

## 뉴스 품질 기준

- 상품별 필수 맥락어가 없는 동음이의 기사는 제외한다(예: 폭스바겐 골프).
- 주가·목표주가·인사·수상·단순 사회공헌·보험사 재무실적은 감점한다.
- 제목 유사도가 높은 같은 사건의 반복 기사는 한 건으로 묶는다.
- 전체 상위 기사 선정 시 카테고리당 한 건을 먼저 뽑아 다양성을 확보한다.
- 텔레그램은 상위 3건, 이메일은 상위 8건, 대시보드는 카테고리별 최대 2건을 표시한다.
- 알림 채널의 뉴스 한 건은 `제목 → 한 문단 요약 → 출처·날짜·원문` 순서로 고정한다.
- 이메일은 가로 다열 표를 사용하지 않고 폭 100%의 1열 카드와 자동 줄바꿈을 사용한다.
- 모든 자동 요약은 공개 뉴스 검색의 제목·설명문 기반이다. 기사 원문 전체를 읽은 요약이 아니다.

`news-clip.yml`이 하루 두 번 클리핑과 공통 브리프를 함께 갱신한다. 새 브리프가
최신 클리핑과 날짜가 다르면 `daily_brief.py`가 발송 직전에 다시 계산한다.

## 반복되는 오늘 할 일

검색수요 급등·기상특보 같은 실시간 신호는 항상 우선 노출한다. 변화가 없는 시즌
업무는 매일 전부 반복하지 않고 하루 한 건만 순환한다. SERP 정기 점검도 최대 한
건만 포함한다. 메시지는 `새 신호 최대 2 + 시즌 집중 1 + SERP 1`을 넘지 않는다.

## 논문 3분 브리프

각 논문에 연구 질문, 공개 설명의 핵심 내용, 연구 방법 확인 여부, CM 업무 적용점,
한계, 확인 범위와 신뢰도를 표시한다. 확인 범위는 `공개 서지·초록 기반`,
`담당자 정리 기반`, `메타데이터만 확인`, `링크만 확인`으로 구분한다.

초록·서지 기반 브리프를 원문 전체 요약으로 표현하지 않으며, 수치·표본·인과관계는
원문에서 다시 확인해야 한다.
