# CM SEO Title Ops

CM-CMO의 공개 검색 수요와 비공개 Search Console 검증을 결합해 파워컨텐츠 제목 후보 3개를 만든다. 결과는 `adcopy-tool.html`의 파워컨텐츠 소재 제안에서만 표시하며, SEO 감사 화면에는 노출하지 않는다. 결과는 항상 근거, 약점, 검토 상태를 함께 제공하고 보험 상품의 자동 게시나 광고심의 승인을 의미하지 않는다.

## 데이터 경계

- 상품 정본은 `data/products.json`, 검색 수요는 `data/volume.json`, 질문 기회는 `data/seo/faq-opportunities.json`을 사용한다.
- `data/search-console.json`은 비공개 입력이다. 원본 검색어, 페이지 URL, 클릭·노출·CTR·평균순위를 커밋하거나 정적 화면에 노출하지 않는다.
- 생성 결과에는 공개 SearchAd 검색어와 수요, GSC 검증 상태의 범주값만 남긴다.
- 고객·임직원 정보, 광고계정 원본, 실제 API 자격증명은 입력·출력·로그에 포함하지 않는다.

## 실행

```bash
python scripts/seo_title_agent.py
```

결과는 `data/adcopy/powercontent-title-opportunities.json`에 기록된다. 출력 스키마를 확인하거나 변경할 때는 [references/title-ops-schema.md](references/title-ops-schema.md)를 읽는다.

## 판정 원칙

1. 한국어 제목은 네이버 검색광고 실측 수요가 있는 검색어를 우선한다. 경쟁사 브랜드 검색어는 후보에서 제외한다.
2. 서로 같은 선택지가 되지 않도록 상황형, 상품형, 범위 제한형 후보를 하나씩 만든다.
3. GSC가 없으면 후보는 `초안`으로만 표시하고 추천 후보를 선택하지 않는다.
4. GSC가 있으면 자기잠식 여부와 검색 가시성 범주를 확인한다. 여러 페이지가 같은 검색어를 점유하면 해당 후보를 반려한다.
5. 현재 권위가 낮으면 헤드 검색어보다 바디·테일 검색어를 우선한다. 4~20위권 신호는 개선 기회로 우선 검토한다.
6. 제목이 실제 파워컨텐츠 본문보다 넓은 약속을 하지 않도록 배포 전에 본문 일치 여부를 확인한다.
7. 보험 상품의 보험료, 한도, 지급 조건, 면책·감액 같은 구체 주장은 자동으로 제목에 만들지 않는다. 추가할 때는 최신 상품자료·약관과 심의 내용을 사람이 확인한다.
8. 모든 결과는 `human_review_required` 상태다. 상품 담당자·준법·광고심의 검토 전 게시하지 않는다.

## 구조화 데이터와 콘텐츠 품질

- FAQ 질문은 검색 의도와 본문 기획에 사용하되 `FAQPage`를 Google 리치결과 혜택으로 권장하지 않는다.
- 보험은 YMYL 영역이므로 출처 기준일, 작성·검토 주체, 제한·예외, 상품 버전을 확인한다.
- 파워컨텐츠 게재 후 7·14·28·56일 단위로 GSC 결과를 읽고 `유지`, `추가 검증`, `롤백`, `미검증` 중 하나로 기록한다.

## 완료 조건

- 후보가 정확히 3개이고 각 후보에 목표 검색어, 검색 수요, 약점, GSC 상태, 검토 상태가 있다.
- 추천은 GSC가 연결됐고 자기잠식이 없는 경우에만 존재한다.
- 공개 산출물에 원본 GSC 행이나 민감한 성과 수치가 없다.
- 제목 길이와 본문 약속, 상품자료·약관, 광고심의 상태를 사람이 최종 확인한다.
